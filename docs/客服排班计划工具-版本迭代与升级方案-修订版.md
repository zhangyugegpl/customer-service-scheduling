# 客服排班计划工具 · 版本迭代与升级方案（修订版）

> 文档版本：1.1  
> 修订日期：2026-09-25  
> 适用范围：客服排班计划工具 1.x 及后续兼容版本。

## 1. 目标与原则

| 目标 | 说明 |
| --- | --- |
| 受管数据不丢失 | 正常磁盘与权限条件下，升级后完整保留员工、岗位、规则、指定日期、边界状态、配置快照、排班历史、人工调整日志和备份 |
| 升级可恢复 | 迁移失败自动恢复；在备份保留范围内可将数据恢复到升级前状态 |
| 平滑引入 | 新功能默认值保持旧版行为；可能改变结果的功能由用户明确启用 |
| 旧版保护 | 旧版检测到更高 schema 时不得写入，防止破坏新数据 |
| 免打扰 | 单机工具不自动在线更新，由用户手动下载和替换程序 |

设计原则：数据与程序分离、稳定 ID、schema 独立版本化、迁移逐级且幂等、写入原子化、迁移前强制备份、失败可恢复、过程可审计。

## 2. 数据范围与目录

### 2.1 程序与数据分离

| 位置 | 内容 | 升级处理 |
| --- | --- | --- |
| 程序目录 | 主 EXE、运行时资源、内置模板、使用说明 | 可整体替换 |
| 应用数据目录 | 当前生效配置、配置快照、边界状态、排班历史、调整日志、迁移日志、备份 | 永不被覆盖式升级直接替换 |
| 用户选择目录 | 导出的 Excel/CSV、用户选择保留的原始导入文件 | 程序升级不处理 |

应用数据目录默认位于系统当前用户的应用数据路径下，并使用产品专属子目录。程序不得依赖注册表保存业务数据。

### 2.2 受管数据对象

升级与恢复必须覆盖以下数据：

- 员工、岗位、技能矩阵、日期配额和规则；
- 指定休息、指定岗位、指定审单、指定休息人数；
- 软约束优化层和权重；
- 上月排班边界状态；
- 配置快照；
- 排班历史、结果状态、求解器版本和随机种子；
- 人工修改日志和有例外方案的确认原因；
- 导出记录及模板版本；
- 迁移日志和备份清单。

导出到用户自选目录的文件不纳入应用备份，但不得在升级过程中被删除或修改。

### 2.3 稳定 ID

员工、岗位、规则、配置快照和排班记录使用不可变 UUID。升级中的字段改名、展示名称变化和结构重组不得重新生成 ID。迁移完成后必须验证所有引用均指向存在的对象。

## 3. 版本策略

### 3.1 程序版本

使用语义化版本 `major.minor.patch`：

- `major`：存在不兼容的程序或数据行为变化；
- `minor`：向后兼容的新功能；
- `patch`：兼容性问题修复。

### 3.2 数据版本

- `schemaVersion`：业务数据结构版本，仅在数据结构变化时递增；
- `templateVersion`：导入/导出 Excel 模板版本，独立于程序和 schema；
- `solverVersion`：排班算法和评分规则版本，随每份排班历史保存；
- `backupFormatVersion`：备份清单格式，保持长期向后兼容，使旧版能够识别可恢复的备份。

每个程序版本必须声明：当前 schema、可直接迁移的最低 schema、支持的模板版本范围和求解器版本。

### 3.3 兼容矩阵

发布包内必须包含兼容矩阵，至少记录：

| 程序版本 | 当前 schema | 最低可迁移 schema | 可读模板版本 | 可恢复备份格式 |
| --- | --- | --- | --- | --- |
| 示例 1.0.0 | 1 | 1 | 1.x | 1 |

低于最低可迁移 schema 的数据不得尝试跳级迁移，应提示先使用指定的中间版本。

## 4. 存储与写入安全

### 4.1 原子写入

配置、排班历史和迁移结果不得直接覆盖活动文件。统一流程为：

1. 在同一数据卷的临时目录写入完整新数据；
2. 执行 schema、引用完整性、记录数量和校验和验证；
3. 写入迁移或保存日志；
4. 通过原子重命名切换活动版本；
5. 切换成功后再清理临时文件。

程序异常、断电或磁盘空间不足时，下次启动必须根据事务标记恢复到最近一次完整状态。

### 4.2 并发与进程锁

- 同一数据目录同一时间只允许一个写入实例；
- 第二个实例以只读模式打开或提示关闭已有实例；
- 升级、迁移、恢复和重置期间必须持有独占锁。

### 4.3 数据重置

“重置默认”只重置当前工作配置，不删除排班历史或旧快照。执行前自动创建快照，并要求用户确认。用户主动清理历史和备份时使用独立入口。

## 5. 数据迁移机制

### 5.1 迁移触发

新版首次启动时读取活动数据的 `schemaVersion`：

- 等于当前版本：直接启动；
- 低于当前且在兼容范围：进入备份和迁移；
- 低于最低兼容版本：停止迁移并提示所需中间版本；
- 高于当前版本：以只读保护模式打开，不得写入。

### 5.2 迁移链

使用逐级迁移函数，例如 `migrate_v1_to_v2`、`migrate_v2_to_v3`。禁止在存在中间版本时直接以一个不可测试的大迁移跨越多个 schema。

每个迁移函数必须：

- 输入和输出 schema 明确；
- 可重复运行且结果一致；
- 不依赖 UI 状态或网络；
- 保留稳定 ID；
- 输出结构化迁移报告；
- 有正向、失败恢复和幂等测试。

### 5.3 字段迁移规则

| 变更类型 | 迁移处理 |
| --- | --- |
| 新增字段 | 填充等同旧行为的默认值，并记录默认值来源 |
| 字段重命名 | 显式映射，稳定 ID 和字段语义不变 |
| 字段删除 | 活动结构不再使用，但原始数据保留在迁移备份中 |
| 枚举扩展 | 保留旧值语义；无法映射时停止迁移并报告对象 |
| 结构调整 | 从只读旧对象构建全量新对象，验证通过后整体切换 |
| 引用变化 | 按稳定 ID 迁移并进行悬空引用检查 |
| 规则变化 | 保留原规则和求解器版本；不得静默重算历史排班 |

### 5.4 完整迁移事务

1. 获取数据目录独占锁。
2. 检查磁盘空间、文件可读性和活动事务状态。
3. 创建升级前完整备份并生成清单与校验和。
4. 在临时目录逐级执行迁移。
5. 校验 schema、引用完整性、对象数量和关键业务字段。
6. 原子切换到新数据版本。
7. 写入成功报告并释放锁。
8. 任一步失败时恢复升级前活动版本，保留失败报告和临时诊断信息。

## 6. 备份与恢复

### 6.1 备份内容

每份备份包含：

- `manifest`：备份格式、程序版本、schema、创建时间、文件清单和校验和；
- 当前生效配置及所有配置快照；
- 排班历史、边界状态和人工调整日志；
- 模板版本和导出记录；
- 最近一次有效迁移日志。

### 6.2 备份策略

- schema 迁移前强制创建完整备份；
- 重置默认、导入覆盖和手动恢复前创建保护性备份；
- 默认保留最近 5 份自动备份；
- 用户标记为“保留”的备份不参与自动清理；
- 清理前验证剩余备份至少有一份可恢复。

因此，“一键回滚”仅承诺在可用备份的保留范围内成立；产品不得宣传为任意历史版本无限期回滚。

### 6.3 恢复方式

在“关于 / 版本与恢复”页面选择备份后：

1. 校验备份清单和文件校验和；
2. 自动备份当前活动数据；
3. 将目标备份恢复到临时目录；
4. 校验目标 schema 和引用完整性；
5. 原子切换活动数据；
6. 提示应使用的程序版本并退出或重新启动。

恢复不得只复制单个配置文件；配置、排班历史和边界状态必须作为一致快照恢复。

### 6.4 降级到旧程序

推荐流程：

1. 在当前程序的恢复页面选择目标旧版本对应的迁移前备份；
2. 恢复完成并关闭程序；
3. 使用目标旧版本程序目录启动；
4. 旧程序核对 schema 后进入主界面。

如果用户先启动旧程序且活动数据 schema 更高，旧程序必须拒绝写入，并提供“选择兼容备份恢复”入口或明确操作指引。旧程序不得自行猜测或静默选择备份。

### 6.5 迁移失败

迁移失败时自动恢复升级前活动版本，不进入业务主界面。页面必须展示失败阶段、错误编号、恢复结果、日志位置和可重试条件，但不得在日志中写入不必要的员工个人信息。

## 7. 历史排班兼容

1. 历史排班保存其配置快照、`solverVersion`、随机种子和结果状态。
2. 升级后历史排班默认只展示，不使用新算法静默重算。
3. 用户主动选择“按当前规则重新生成”时创建新版本，不覆盖旧记录。
4. “可发布”“有例外”“无可行方案”的状态含义不得在小版本升级中改变。
5. 跨月边界状态必须与来源排班记录关联，防止删除或替换上月排班后产生不可追溯数据。

## 8. 模板兼容

### 8.1 导入模板

- 导入文件必须声明 `templateVersion`；
- 当前程序仅接受兼容矩阵中声明的版本；
- 旧模板可自动转换时，先展示转换预览，再创建配置快照；
- 无法安全转换时拒绝导入，并提供对应空白模板。

### 8.2 导出模板

- 每个程序版本绑定明确的黄金导出样例；
- 模板升级不得改变历史文件；
- 公式字段同时写入公式和缓存结果；
- 模板主版本变化应保留旧模板导出能力，直至兼容策略声明的截止版本。

## 9. 新功能引入

| 手段 | 规则 |
| --- | --- |
| 等同旧行为的默认值 | 新字段的默认值不得改变老用户现有排班语义 |
| 功能开关 | 仅用于会改变结果或流程的新功能，默认关闭 |
| 独立 schema 迁移 | 不通过 UI 隐式补字段，必须由迁移函数完成 |
| 历史版本保留 | 启用新算法后生成新排班版本，不覆盖旧结果 |
| UI 渐进 | 新入口不得阻断配置、生成、调整、导出的主流程 |

功能开关本身属于受管配置，必须纳入快照、备份和迁移。已经正式稳定且所有用户都应使用的功能，应在主版本规划中移除开关，避免永久分叉。

## 10. 端到端升级流程

1. 用户下载并解压新版程序包到新的程序目录，或按说明替换原程序目录。
2. 用户启动新版主 EXE。
3. 程序获取数据锁并检查程序版本、schema、模板及未完成事务。
4. 如需迁移，执行环境检查、强制备份、临时目录迁移和完整性校验。
5. 校验成功后原子切换活动数据，并生成迁移报告。
6. 迁移成功进入主界面；失败则自动恢复并进入恢复说明页。
7. 用户在“关于 / 版本与恢复”查看程序版本、schema、模板版本、求解器版本、备份和迁移报告。

便携模式列为 P1。启用便携模式时，升级页面必须检测程序目录内的 `data`，阻止用户在未确认备份的情况下执行覆盖升级。

## 11. 验收标准

| 项 | 验收标准 |
| --- | --- |
| 数据保留 | 升级后稳定 ID、配置、边界状态、排班历史、调整日志和备份记录完整 |
| 历史一致性 | 历史排班保持原配置、求解器版本和结果状态，不被静默重算 |
| 迁移正确 | 新增、重命名、删除、枚举、结构和引用变化均符合迁移规则 |
| 迁移幂等 | 同一输入重复迁移得到相同输出，不产生重复对象 |
| 原子写入 | 任意迁移步骤异常后，活动数据仍是完整旧版本或完整新版本，不出现半迁移状态 |
| 失败恢复 | 注入迁移异常、断电标记、磁盘空间不足后均能恢复到最近有效状态 |
| 旧版保护 | 旧版面对更高 schema 时拒绝写入，并能引导选择兼容备份 |
| 手动恢复 | 备份校验、当前状态保护、完整快照恢复和版本提示均正确 |
| 重置保护 | 重置前自动创建快照，不删除历史排班和旧配置 |
| 备份管理 | 默认保留最近 5 份；保留标记生效；无可恢复备份时禁止清理最后有效副本 |
| 模板兼容 | 支持范围、转换预览、拒绝策略和黄金样例比对符合兼容矩阵 |
| 敏感数据 | 日志不记录不必要的员工姓名、完整排班内容或原始导入文件内容 |

## 12. 发布门禁

每次发布前必须完成：

1. 从最低兼容 schema 到当前 schema 的逐级升级测试；
2. 每一跳迁移函数的成功、失败恢复和幂等测试；
3. 当前版本升级后再恢复到升级前备份的测试；
4. 旧程序读取高版本数据时的只读保护测试；
5. 配置、排班历史、边界状态和人工日志的对象数量与引用一致性比对；
6. 导入模板兼容测试和黄金导出样例比对；
7. 绿色版在干净 Windows 10/11 x64 环境的首次启动测试；
8. 迁移报告、错误提示和恢复说明的可读性检查。

任一数据损坏、悬空引用、静默丢字段、半迁移状态或旧版误写问题均为阻断发布缺陷。

## 13. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 用户覆盖程序目录时误带数据 | 默认数据目录独立；便携模式升级前强制备份和确认 |
| 跨大版本迁移复杂度失控 | 最低兼容版本 + 逐级迁移链 + 每一跳自动化测试 |
| 旧版破坏新数据 | 高 schema 只读保护 + 稳定备份清单 + 显式恢复流程 |
| 迁移中断产生脏数据 | 临时目录写入 + 校验和 + 原子切换 + 事务标记 |
| 备份占用空间 | 默认保留 5 份、允许标记长期保留、清理前验证可恢复性 |
| 排班算法变化影响历史 | 保存 solverVersion；历史只读；重新生成创建新版本 |
| 员工改名导致引用断裂 | UUID 关联；名称仅展示；迁移后检查悬空引用 |
| 日志泄露员工信息 | 结构化错误码、最小化记录、敏感字段脱敏 |
