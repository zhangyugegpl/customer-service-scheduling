## 1. 产品概述

面向售后组主管的月度排班工具：按岗位模板一键生成满足全部硬约束、尽量满足软约束的排班表，并导出符合版本化模板的 Excel 与 CSV。人员、岗位、规则全部配置化，支持通过 Excel 批量初始化，推广到新团队时无需修改代码。

| 项 | 内容 |
| --- | --- |
| 目标用户 | 售后组主管 |
| 产品形态 | Windows 绿色版 EXE，解压即用、免安装、免预装运行时 |
| 交付形态 | 单个 zip/7z 压缩包，解压后双击主 EXE 使用 |
| 核心价值 | 把手工排班从「反复调整 Excel」变为「配置规则 → 预检查 → 一键生成 → 校验微调 → 发布导出」 |
| 运行边界 | 单机、本地数据、无后端、无网络依赖 |

## 2. 产品目标与范围

### 2.1 核心目标

1. **可靠排班**：生成满足全部硬约束、按优先级优化软约束的月度排班。
2. **规则可配置**：人员、岗位、技能、休假规则、约束优先级、指定日期均可视化维护。
3. **问题可定位**：生成前发现配置冲突；生成后将违规定位到规则、员工和日期。
4. **调整可控**：支持强制改单格和智能调班，所有人工修改可追溯。
5. **结果可交付**：导出版本化 Excel 模板和带 BOM 的 CSV，并保留排班历史。
6. **持续可用**：支持上月排班衔接、配置迁移、备份和恢复。

### 2.2 MVP 范围外

- 多人在线协作、账号权限和云端同步；
- 自动在线升级；
- 考勤打卡、工资核算和实时工单量预测；
- 手机端应用。

## 3. 核心业务口径

### 3.1 每日唯一状态

1. 每名在职员工在目标月份的每个自然日必须且只能处于一个状态：`休息`或某一个已配置岗位。
2. 员工只能被安排到其技能矩阵允许的岗位。
3. 岗位配额为当日最低人数要求，不是精确人数；满足最低配额后，多余的上班员工可被安排到其具备技能的任一岗位。
4. 不设置“弹性日”，也不设置未归属岗位的“机动”状态。
5. 当现有人员、技能和休息要求无法同时满足岗位最低配额时，判定为硬约束不可行。

### 3.2 自然周与跨月规则

1. 每周按周一至周日计算。
2. 目标月月初所在自然周如包含上月日期，应读取上月排班尾部并合并计算。
3. 目标月月末所在自然周如延伸到下月，先保存本月末边界状态；生成下月排班时，与下月月初合并完成该自然周的完整校验。
4. 连休、连续上班、休中休和倒班均跨月计算：生成本月时读取上月末连续状态，生成完成后保存本月末连续状态供下月使用。
5. 上月排班解析失败时允许手动录入边界数据。用户确认跳过时，可以继续生成，但结果必须提示“跨月规则未完整校验”。

### 3.3 规则冲突处理

1. 同一员工同一日期只能存在一条有效的状态锁定。
2. 完全相同的重复指定可自动去重；互相矛盾的指定必须在预检查阶段阻止生成。
3. 指定休息人数不得少于该日已指定休息的员工数，也不得大于在满足岗位最低配额后的最大可休人数。
4. 指定岗位员工必须具备对应岗位技能；不满足时视为配置错误，不进入求解。
5. 所有配置引用使用稳定 ID；姓名和岗位名称仅用于展示，不作为关联主键。

## 5. 业务规则

### 5.1 硬约束

硬约束决定排班是否可发布。正式可发布排班不得违反任何硬约束。

| 编号 | 规则 |
| --- | --- |
| H1 | 每名在职员工每天必须且只能处于一个状态：休息或一个岗位 |
| H2 | 每日各岗位实际人数必须大于或等于该日最低配额；员工必须具备所分配岗位的技能 |
| H3 | 每人当月休息天数必须精确等于其配置值 |
| H4 | 三人组：组内同一日期最多休息 1 人 |
| H5 | 互斥对：同一对员工不可在同一日期休息 |
| H6 | 指定休息日：员工当日固定休息，不可被自动或智能调班移动 |
| H7 | 指定岗位日：员工当日固定为指定岗位且不可休息，员工须具备对应技能 |
| H8 | 指定日期休息人数：该日实际休息人数必须等于指定值 |
| H9 | 指定审单日：员工当日固定为审单岗，不可移动，且须具备审单技能 |

补充规则：

- 未指定每日休息人数的日期，由求解器在满足 H2、H3 及其他硬约束的前提下决定。
- 岗位最低配额可按具体日期覆盖默认值，用于周末、节假日或特殊日期。
- 三人组允许配置多个组；员工可以属于多个组，每个组分别校验。重复组自动去重。

### 5.2 软约束

| 编号 | 规则 | 默认优化层 |
| --- | --- | --- |
| S1 | 倒班规避：减少岗位频繁切换，倾向块状轮换 | 最高 |
| S2 | 中班均匀：可上中班员工的中班天数极差 ≤ 3 | 高 |
| S3 | 连休段：每人尽量有 1～2 个连续 2 天休息段 | 中 |
| S4 | 休中休：两次休息之间连续上班天数尽量落在 [3, 6] | 中 |
| S5 | 每周上班：完整自然周上班 3～6 天，优先上 6 休 1 | 低 |

软约束按优化层级依次处理：硬约束 → 用户勾选的最高优先级软约束 → 未勾选软约束的默认层级。同一层内使用标准化后的违规分数加权求和，避免不同计量单位导致权重失真。

跨月计算口径：

- 月初残缺周与上月末对应日期合并计算 S5；
- 月末残缺周保存边界数据，在下月生成时完成整周校验；
- S1、S3、S4 读取上月末连续状态并跨月计算。

### 5.3 预检查

点击生成前必须执行预检查，至少包括：

- 必填、枚举、数值范围和稳定 ID 引用完整性；
- 每日岗位最低配额之和是否超过在职员工数；
- 每个岗位具备技能的人数是否足以覆盖最低配额；
- 月休天数是否超过目标月天数；
- 指定休息、指定岗位、指定审单之间是否冲突；
- 指定休息人数是否超出当日可行范围；
- 三人组、互斥对与指定休息是否形成必然冲突；
- 上月边界数据是否齐全、月份是否连续。

预检查发现结构或引用错误时阻止求解；发现上月数据缺失时允许用户补录或确认降级校验。

### 5.4 结果状态与无解降级

| 状态 | 判定 | 产品行为 |
| --- | --- | --- |
| 可发布 | 所有硬约束满足 | 可保存为正式版本并正常导出 |
| 有例外 | 无合法解，近似方案存在硬约束违规 | 展示违规来源；仅在用户确认并填写原因后允许带“例外方案”标识导出 |
| 无可行方案 | 未能形成完整排班，或输入配置无效 | 不允许正式导出，引导修改配置后重算 |

有例外方案的每条违规必须输出：规则编号、员工、日期、实际值、期望值、冲突来源和建议调整方向。系统不得将有例外方案默认标记为正式排班。

## 6. 配置与数据模型

### 6.1 稳定标识

- `employeeId`、`positionId`、`ruleId`、`scheduleId`、`snapshotId` 使用不可变 UUID。
- 员工姓名、岗位名称允许修改；修改展示名称不得破坏既有排班和规则引用。
- Excel 导入时优先按员工编号或稳定 ID 匹配；首次导入时生成 UUID。
- 姓名重复且无员工编号时必须要求用户消歧，禁止静默合并。

### 6.2 核心数据对象

- `employees`：员工 ID、姓名、员工编号、状态、技能岗位、月休天数；
- `positions`：岗位 ID、名称、语义色、默认最低配额、按日期覆盖配额；
- `rules`：三人组、互斥对、区间参数、跨月口径；
- `weights`：软约束优化层与同层权重；
- `specifiedDays`：指定休息、指定岗位、指定审单、指定休息人数；
- `boundaryState`：上月末排班日期、连续上班/休息长度、最近岗位序列和残缺自然周数据；
- `scheduleRecords`：月份、结果状态、配置快照、求解器版本、随机种子、排班结果、人工调整日志和导出记录。

排班算法必须是纯函数：接收版本化配置、目标月份和边界状态，返回排班结果、评分和结构化问题列表。业务规则不得硬编码具体员工、岗位或人数。

### 6.3 批量导入模板

导入模板必须包含 `templateVersion`，模板结构如下：

| Sheet | 内容 | 关键列 |
| --- | --- | --- |
| 员工信息 | 员工及技能 | 员工编号 / 姓名 / 可任岗位 / 月休天数 |
| 岗位与配额 | 岗位和最低人数 | 岗位 / 颜色 / 默认最低配额 |
| 日期配额 | 特殊日期岗位最低人数 | 日期 / 岗位 / 最低配额 |
| 排班规则 | 规则参数 | 类型 / 成员或成员编号 / 参数值 |
| 约束优先级 | 软约束优化层 | 约束项 / 是否最高优先级 / 同层权重 |
| 指定日期 | 指定员工状态或休息人数 | 员工编号 / 日期 / 指定类型 / 岗位或人数 |

导入流程：上传 → 解析 → schema 校验 → 业务预检查 → 错误清单预览 → 用户确认 → 创建配置快照。导入覆盖现有配置前必须自动备份当前快照。

### 6.4 排班历史

每次生成、智能调班和正式保存均形成可追踪版本。历史记录至少保存：

- 目标月份和结果状态；
- 所用配置快照 ID、边界状态和模板版本；
- 求解器版本、随机种子、软约束评分；
- 人工修改前后值、操作时间和确认原因；
- 导出时间、格式和文件名。

## 7. 用户流程

### 7.1 首次初始化

1. 解压并启动主程序，进入配置管理引导。
2. 下载当前版本导入模板并填写员工、岗位和规则。
3. 上传模板，查看 schema 校验和业务预检查结果。
4. 修正错误并确认初始化，系统生成首个配置快照。

### 7.2 月度排班

1. 选择目标月份并确认人员、岗位、规则和日期配额。
2. 上传上月排班；解析失败时手工补录边界数据，或确认按降级口径继续。
3. 配置修改后系统自动进行轻量校验，并将旧排班标记为“配置已变化”。
4. 点击“一键生成”，运行完整预检查和求解。
5. 查看结果状态、月视图和问题清单。
6. 使用强制修改或智能调班完成调整。
7. 保存正式排班版本，再导出 Excel 或 CSV。

### 7.3 手动调整

**强制修改**：用户直接修改员工某日状态，系统立即更新岗位人数、休息数和规则校验；若产生硬约束违规，结果状态立即变为“有例外”。

**智能调班**：用户选择员工、日期和目标状态，系统返回可交换人员或最小影响调整方案，展示应用前后的硬约束状态和软约束评分；用户确认后一次性应用并记录日志。

锁定的指定休息、指定岗位和指定审单不可被智能调班移动。强制修改锁定状态前必须先解除对应指定规则。

### 7.4 多方案

P1 支持保留配置重新生成候选方案。候选方案除随机种子外，还应设置最低差异度，避免输出几乎相同的结果。每份候选方案展示各软约束得分和总评分。

## 8. 界面与交互

- 顶部工具栏：目标月份、生成、重新排班（P1）、保存版本、导出、重置。
- 主体 Tabs：排班预览 / 人员与岗位 / 排班规则 / 上月衔接 / 历史记录 / 配置管理。
- 配置变化后仅执行 300ms 防抖的轻量校验，不自动重新求解；旧结果显示“配置已变化，需重新生成”。
- 求解在后台工作线程运行，提供运行状态、取消和超时提示，不阻塞界面。
- 排班表支持横向滚动、冻结员工列、岗位语义色、违规高亮和单格操作。
- 指定日期支持日期选择器与批量文本输入；文本输入兼容 `4、5、6`、`4 5 6`、`4,5,6`、`4日、5日`，保存时统一转换为完整日期。
- 有例外方案在页面顶部持续显示醒目标识，导出前再次确认。
- “重置默认”先自动创建配置快照，再重置当前工作副本，不删除历史排班或旧快照。

## 9. 导出规格

### 9.1 版本化模板

- 每个导入和导出模板均有独立 `templateVersion`。
- 项目交付物必须包含空白模板、字段说明和黄金导出样例。
- 模板验收范围包括 Sheet 名、行列位置、列宽、冻结窗格、合并单元格、颜色、公式和打印区域。
- 模板发生不兼容变化时递增主版本，并提供迁移或兼容说明。

### 9.2 Excel

- 排班明细和统计按黄金样例生成。
- `COUNTIF`、`SUM`、`COUNTA` 等公式使用英文函数名和逗号分隔符。
- 公式单元格同时写入公式和由程序计算的缓存结果，确保未打开 Excel 重算时也能展示正确数值。
- 导出过程不依赖目标机安装 Office 或 WPS。
- 有例外方案的工作簿必须包含显著的“例外方案”标识和确认原因。

### 9.3 CSV

- CSV 仅导出排班明细的值，不包含格式、公式或多 Sheet 内容。
- 编码为 UTF-8 with BOM，日期和岗位字段格式固定。
- 有例外方案增加结果状态和确认原因字段。

## 10. 验收标准

| 模块 | 验收项 |
| --- | --- |
| 唯一状态 | 任意员工任意日期有且仅有一个状态，不出现重复排班或状态缺失 |
| 岗位与技能 | 每日岗位人数不低于最低配额；所有岗位分配均符合技能矩阵 |
| 月休 | 每人当月休息天数精确等于配置值，不使用弹性日 |
| 指定日期 | 冲突指定在预检查阶段被阻止；合法指定在生成和智能调班中保持锁定 |
| 约束优先级 | 被勾选软约束进入同一最高优化层，结果评分可重复计算 |
| 跨月衔接 | 月初残缺周、连休、连续上班、休中休和倒班正确读取上月边界；本月末边界正确保存供下月使用 |
| 结果状态 | 可发布、有例外、无可行方案三种状态判定和导出限制符合定义 |
| 配置校验 | 容量、技能、引用和指定日期冲突能在求解前定位 |
| 手动调整 | 强制修改即时校验；智能调班展示影响并保持锁定规则；操作写入日志 |
| 稳定 ID | 员工或岗位改名后，既有规则和历史排班引用不丢失 |
| Excel 导出 | 与黄金样例结构一致；公式与缓存结果正确，可由 Excel/WPS 重算 |
| CSV 导出 | UTF-8 BOM，中文不乱码，字段及值与排班明细一致 |
| 历史记录 | 可按月份查看排班版本、配置快照、调整日志和导出记录 |
| 配置维护 | 配置可保存、导入、导出、恢复和带备份重置，重启后不丢失 |
| 交互性能 | 基准数据下轻量校验 P95 < 300ms；求解不阻塞 UI，可取消 |
| 求解性能 | 基准规模 9 人 × 31 天 × 4 岗位，在约定标准测试机上求解 P95 < 3 秒；超时返回明确状态而非卡死 |

标准测试机、基准配置和测试数据必须随测试方案固化。超过基准规模时不承诺上述求解时延，但仍须保持 UI 可响应。

## 11. 优先级与依赖

### 11.1 MVP P0

- 配置 schema、稳定 ID、配置快照和排班历史；
- 上月边界解析与手工补录；
- 预检查、硬约束求解和软约束优化；
- 三种结果状态及有例外方案的导出限制；
- 月视图、校验警示、强制修改和智能调班；
- 版本化 Excel/CSV 导入导出；
- 迁移、备份、恢复和绿色版打包。

### 11.2 P1

- 多候选方案及差异度控制；
- 统计面板；
- 岗位筛选导出；
- 便携数据模式。

### 11.3 实现依赖

1. 可计算规则与测试样例 → 数据 schema → 预检查器 → 求解器。
2. 求解器 → 排班预览与即时校验 → 强制修改与智能调班。
3. 版本化模板与黄金样例 → 导入导出实现及自动化比对。
4. 稳定 ID、schemaVersion 和原子化存储 → 历史记录、迁移和恢复。
5. 上月边界数据模型必须在求解器开发前确定。

## 12. 打包、运行与数据位置

### 12.1 打包

- 交付单个 zip/7z，解压后双击主 EXE 使用。
- 采用 Electron 自包含打包，内置渲染和运行时，不依赖目标机的 Node、Python、浏览器、Office 或 WPS。
- Windows 10/11 x64，不写注册表、不要求管理员权限、无后台常驻。

### 12.2 启动

1. 启动主 EXE，加载应用数据目录中的 schema 和当前生效配置快照。
2. 检查迁移状态；需要时先备份并执行迁移。
3. 首次启动进入配置向导；非首次启动默认进入下月排班。
4. 关闭主窗口后退出全部进程。

### 12.3 数据位置

- 程序目录只保存 EXE、运行时、内置模板和说明；升级时可整体替换。
- 应用数据目录保存配置、边界状态、排班历史、调整日志和备份；不得在升级时覆盖。
- 用户上传的原始 Excel 可选择是否归档；导出文件默认由用户选择保存位置。
- 程序目录与数据目录物理分离。便携数据模式列为 P1，启用时必须显示覆盖升级风险。

## 13. 开发前必须具备的验收资产

1. 一份合法且存在可发布解的匿名数据集；
2. 一份只能牺牲部分软约束的数据集；
3. 一份因硬约束冲突而不可行的数据集；
4. 一份包含月初跨月连续状态的上月排班样例；
5. 一份版本化导入模板和字段说明；
6. 一份黄金 Excel 导出样例；
7. 每条 H/S 规则至少一个正例、反例和边界测试。
