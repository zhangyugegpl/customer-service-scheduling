# 安装、验证与常见问题

## 1. 最省事的使用方式

最终用户无需安装 Node.js 或 Python：从 `release` 目录获取 `客服排班计划工具-0.1.0-x64.exe`，双击运行即可。ZIP 版适合归档或统一分发。

首次启动会在 Electron 的用户数据目录下创建 `scheduler-data`，其中包含配置、排班历史、跨月边界和最多 5 份滚动备份。应用离线运行，不上传业务数据。

## 2. 开发环境要求

- Windows 10/11 64 位；
- Node.js 22.12 或更高版本；
- npm 10 或更高版本；
- Python 3.11～3.12 64 位；
- Git 2.40 或更高版本（仅开发需要）。

在项目根目录执行：

```powershell
scripts\setup.cmd
```

需要安装后立即跑完整验证时：

```powershell
scripts\setup.cmd -Verify
```

脚本会执行版本检查、`npm ci`、Python 本地依赖安装和求解器健康检查。Python 包写入项目的 `.python-packages`，不污染系统环境，也避免中文路径下创建虚拟环境偶发失败的问题。

## 3. 常用命令与验证标准

```powershell
npm run dev                # 启动开发模式
npm run verify             # 类型检查、单元/集成测试、生产构建、求解器健康检查
npm run test:e2e           # Electron 用户全流程测试
npm run release            # 测试后生成 Windows EXE 与 ZIP
```

成功标志：

- 求解器输出 `{"ok":true,"solverVersion":"1.0.0"}`；
- Vitest 全部通过；
- Python unittest 全部通过；
- E2E 输出 `E2E_OK`；
- `release` 目录同时出现 `.exe` 与 `.zip`。
- `release/SHA256SUMS.txt` 包含两项发布文件的 SHA-256，可用 `Get-FileHash` 复核。

## 4. 环境变量

这些变量均为可选项，通常无需设置：

| 变量 | 作用 | 示例 |
| --- | --- | --- |
| `CSS_SCHEDULER_DATA_DIR` | 指定配置、历史和备份的数据目录 | `D:\客服排班数据` |
| `CSS_SOLVER_PATH` | 指定自定义求解器 EXE 或 `main.py` | `D:\tools\scheduler-solver.exe` |
| `CSS_PYTHON_EXECUTABLE` | 开发模式指定 Python 命令 | `C:\Python312\python.exe` |
| `HTTPS_PROXY` | 企业网络下载 npm/pip 依赖时使用的代理 | `http://127.0.0.1:7890` |
| `ELECTRON_MIRROR` | Electron 下载镜像根地址 | 按组织镜像服务配置 |

仅对当前 PowerShell 会话设置的示例：

```powershell
$env:CSS_SCHEDULER_DATA_DIR = 'D:\客服排班数据'
$env:CSS_PYTHON_EXECUTABLE = 'C:\Python312\python.exe'
npm run dev
```

## 5. 常见问题

### PowerShell 提示禁止运行脚本

使用仓库自带的 CMD 入口 `scripts\setup.cmd`。或只为当前进程放开：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
```

### `npm ci` 下载失败、超时或证书错误

确认代理/企业证书配置后重试。不要删除 `package-lock.json`，它用于锁定可重复安装版本。可先运行 `npm cache verify` 检查缓存。企业网络应优先使用组织批准的 npm 镜像。

### pip 找不到 OR-Tools 或安装超时

确认使用 64 位 Python 3.11～3.12：

```powershell
python --version
python -c "import struct; print(struct.calcsize('P') * 8)"
```

然后重跑 `scripts\setup.cmd -SkipNpm`。依赖会覆盖更新到 `.python-packages`。

### 中文目录下 `python -m venv` 失败

本项目不依赖虚拟环境，安装脚本使用 `pip --target .python-packages`。无需创建 `.venv`。若必须使用虚拟环境，可将仓库移动到纯英文短路径后再创建。

### 应用提示“数据目录已被另一个实例占用”

先关闭所有应用实例。应用会自动清理已退出进程遗留的失效写锁；若仍提示占用，在任务管理器确认没有“客服排班计划工具”进程后重新启动。不要在应用运行中手工删除数据文件。

### 生成排班提示跨月规则未完整校验

在“上月衔接”页导入上月排班，或录入每名员工月初前 6 天的状态。未提供边界时仍可生成当月方案，但系统会明确标记跨月校验不完整。

### 打包时报 `spawn EPERM`

这是 Windows 安全软件或受限终端拦截 esbuild/PyInstaller 子进程。关闭占用进程，使用普通本地 PowerShell 重试 `npm run release`；必要时为项目目录配置组织批准的安全软件白名单。

### Windows 报未签名应用或 SmartScreen 提示

当前构建为未签名的内部便携版。仅从受信任的项目发布目录分发，并核对文件哈希。正式面向外部发布前，应在 electron-builder 中配置组织的 Windows 代码签名证书。

## 6. 数据备份与恢复

在“配置管理”页可手动创建或恢复备份。重置配置和恢复操作前系统会自动创建保护性备份。建议将整个 `scheduler-data/backups` 目录纳入公司文件备份策略；恢复后应重新检查岗位配额、指定日和跨月边界。
